# DNS、路由和连接生命周期检查

日期：2026-10-18；修复前基线：`2bb1f59`。

本次检查确认并修复两项可重现的运行状态问题。它们可能影响长时间运行后的分流与连接恢复，但尚未通过受影响网站的实际请求证明是 Cloudflare 拦截的直接原因。

## 共享 IP 的域名关联覆盖

旧实现只为每个 IP 保存最后一次查询的域名。多个域名共用 CDN IP 时，即使前一个域名的 TTL 尚未到期，后一个域名的 DNS 回答也会覆盖它，导致后续 TUN 连接可能套用另一个域名的直连或精确路由规则。

修复后，每个域名与 IP 的关联独立保留 TTL，只有唯一的有效域名才作为关联提示。存在多个有效域名时显示并使用实际 IP，按已有全局模式、IP 精确规则、IP 网段及默认路由判定。关联过期和 TTL 为 0 的回答不会删除其他域名的有效关联。总计最多保留 8192 个关联，共享 IP 的多个域名同样计入上限。

回归通过可控单调时钟推进到第 10、20、30 分钟，验证冲突产生、冲突域名到期、所有关联到期及路由结果；另外覆盖 IPv4、IPv6、同一域名续期、零 TTL、CNAME 和容量淘汰。旧的“展示最后查询域名”测试调整为“共享 IP 不假定属于最后查询域名”，实际连接目的 IP 保持不变。

## HTTP/2 失效连接反复复用

旧实现中，等待流额度或 CONNECT 响应超时仅关闭单个请求。对端不再响应、TCP 通道却仍显示活跃时，后续请求会继续复用旧主连接；持续写入又可能推迟总空闲超时，导致无法及时恢复。

修复复用已有 PING 测量逻辑：请求超时后，每条主连接同时最多进行一次探测。PING 成功则保留连接；5 秒探测超时后淘汰当前失效连接，让后续请求重新建连。目标响应慢或流额度不足本身不触发重连。探测不会重放失败请求，也不会误关闭已经因 GOAWAY 排空的旧主连接。

回归使用本机 TLS/HTTP/2 服务，先完成握手和 PING，再模拟 TCP 保持连接但 HTTP/2 不再收包。分别覆盖等待流额度和等待 CONNECT 响应，验证失效连接被淘汰、下一请求重新连接成功。反向用例验证服务端仍能回 PING 时，即使目标暂不返回 CONNECT 响应或流额度为 0，也继续复用健康连接。
