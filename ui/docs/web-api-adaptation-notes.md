# Web API 适配记录

日期：2026-10-09。依据：[内核 Web API](../../docs/web-api.md)，并核对 `KernelControl`、`ControlApi`、`ControlTasks`、`ControlHttpServer` 的实际响应。

## 本次实现

- 将 `--ui` 和 stdin/stdout 命令完全替换为 `--web --port 0 --config ... --endpoint-file ...`。发现文件只接受 `127.0.0.1` 的 HTTP API v1 地址，所有管理请求附带 Bearer 令牌并禁止重定向。
- 内核独立于 UI 生命周期。启动前优先连接现有内核，使用启动锁避免多个 UI 同时创建进程；关闭 UI 不发送退出命令。显式退出只通过管理 API，不根据发现文件 PID 杀进程。
- 多连接、公共设置和路由草稿通过完整 `PUT /config` 原子提交，避免一次应用拆成多次更新造成中间状态。即时默认切换、规则文件重载、保存使用各自 API。
- 配置默认以内核为准：首次连接、配置版本变化或管理实例变化时自动同步页面，替换未应用草稿；同版本快照、普通状态和日志通知保留编辑内容。应用按钮连续执行 `PUT /config` 与 `POST /config/save`，保存使用本次应用返回的版本；两个接口不是一个事务，保存失败时明确提示已应用但未确认保存成功。409 自动读取内核最新配置，不重试写入。
- 密码通过 `hasPassword` 判断存在，留空时省略 password 字段；全量替换允许清除用户名、CA、验证名称。保留文件规则来源，避免读取后不小心变成空内联规则。
- SSE 支持完整帧、多行 data、CRLF、注释心跳、Last-Event-ID、退避重连和过期快照恢复。配置/状态/日志/任务分别处理，隧道数量不靠 UI 定时查询。
- 连接测试、取消和路由解释采用异步 operations；日志按结构化级别精确筛选。UI 的日志筛选只作用于同一份完整缓存，不涉及服务器筛选游标切换。
- Java 运行时增加 `jdk.httpserver`。删除旧配置迁移和钥匙串接入，配置读取及保存统一由内核负责。

## 接口问题与建议

### 1. 配置保存改变了密码存储边界

现状：`POST /config/save` 将密码写入 `kernel.json`，查询时隐藏密码。权限 600 限制其他用户读取，但文件中的密码未加密。

本次处理：遵循内核单一配置源，在密码输入说明和保存操作中明确告知。没有另建一份看似无密码、实际与内核运行状态不一致的配置。

建议：若产品仍要求只在系统安全存储中保存密码，内核需支持凭据引用或凭据提供器，并明确重启时如何解析；仅让 UI 隐藏字段不足以实现这一要求。

### 2. 缺少诊断任务列表，快照无法完整恢复诊断历史

现状：只有按 ID 获取任务的 `GET /operations/{id}`，SSE snapshot 只包含 status，没有任务 ID 列表。新打开的 UI 不知道之前已完成任务的 ID。

本次处理：当前会话通过 SSE 和 POST 响应保留任务；SSE 快照恢复时重读已知 ID，过期任务移除。重新打开 UI 后不声称已恢复全部历史。

建议：增加有界 `GET /operations`，或在快照中包含可查询的任务 ID。任务列表应提供类型、profileId、target，方便多个并发任务辨认。

### 3. 完整配置校验错误缺少具体位置

现状：`ConfigurationEditor.parse` 对多数校验失败统一返回 `INVALID_CONFIGURATION`，field 为 `configuration`。用户无法区分具体连接、无效字段、规则行号或证书内容问题。

本次处理：UI 提交前验证常见字段范围、重复端点和证书文件存在性；提供“校验配置”以及 API 中文错误信息和错误代码。实际证书解析、规则加载仍由内核判断。

建议：保留结构化错误路径，例如 `connections[id].config.tls.ca`、`local.routesInline` 和规则行号。错误信息应避免附带密码或完整认证头。

### 4. 启动阶段错误无法通过管理日志获取

现状：独立进程在管理接口建立之前失败时，HTTP 日志接口尚不可用；内核启动异常主要写入进程标准错误。UI 为支持退出后继续运行而使用 detached 启动，因此不会依赖标准错误管道。

本次处理：等待属于本次启动 PID 的发现文件，超时终止本次创建的进程并提示检查 Java、JAR、配置。不会终止从旧发现文件读出的其他 PID。

建议：内核支持受限权限的启动日志文件或启动失败报告文件，保留错误代码、时间及脱敏原因，使 UI 可以展示具体原因。

## 验证范围

- Flutter 静态分析与桌面页面测试、不读取旧配置和钥匙串、密码省略/保留与文件规则模型。
- HTTP 测试服务验证管理鉴权、多行 SSE、断线续传、快照恢复、基线保留及拒绝非本机发现地址。
- 真实 Web 内核验证实际转发、在线规则/监听修改、绑定失败回退、配置冲突、保存权限、独立生命周期、重新接管、重启后重新读取与空配置。
- 真实 HTTP/2、HTTP/3 本机服务验证转发、默认连接切换、在线改名、规则热更新与断开重连。

未更改内核 API；上述建议留待内核后续迭代。
