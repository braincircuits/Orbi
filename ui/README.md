# Network 代理客户端

Flutter 桌面客户端，界面以 Flutter Material 和基础组件实现统一桌面侧栏、分层概览、工具栏与侧边编辑；当前已接入 macOS 原生宿主。通过本机 HTTP API 管理代理内核，通过 SSE 接收状态、活跃隧道、日志与诊断进度。接口依据 [内核 Web API](../docs/web-api.md)，要求支持 `--web` 的 API v1 内核。

本目录是 `network` 仓库的 `ui/`，与 Java 内核统一由根目录 Git 管理。以下命令均在 `ui/` 中执行，脚本默认以内核所在的父目录为 `CORE_ROOT`；Flutter 包名仍为 `network_ui`。提交统一在仓库根目录使用 `sh scripts/commit.sh`。构建缓存和根目录 `release/` 发布产物不纳入版本控制，首次检出后需要重新构建。

## 界面

连接页支持名称和地址搜索、协议筛选、卡片／列表切换、定位当前默认连接和每批 12 项惰性显示。点击卡片或列表行只打开侧边编辑器，编辑面板的“设为默认连接”单独切换实际连接；筛选、视图和编辑草稿在页面切换后保留。浏览区与编辑器独立滚动，编辑操作固定在底部。

本地监听和内核运行环境位于侧栏“设置…”面板，也可使用 ⌘, / Ctrl+, 打开。关闭面板保留草稿；“应用并保存”沿用现有完整配置应用流程，会同时保存连接、路由与本地设置的未应用修改。

数据库可在“设置 → 数据库 → 配置数据库”选择 SQLite、PostgreSQL 或 MySQL，填写连接信息后单独“保存并重启内核”。现有连接会断开，新空库从空配置开始，原数据保留；切换失败后可在此修正或重新选择原库。详细说明见 [数据库配置](../docs/database-storage.md)。

## 使用

日常验证使用 `scripts/package-macos-jar.sh` 生成包含 JAR 和 Java 运行时的 macOS 包；仅在明确要求时构建 AOT 原生内核。隧道路由菜单统一使用紧凑行高、轻阴影与中性表面；待应用草稿与未保存状态在编辑器和底部状态栏明确提示。概览以浅强调色面板突出服务状态和启停操作，发送、接收、隧道与延迟采用独立指标面板，流量趋势置于全宽面板。启动使用主色实心按钮，停止使用错误语义色。连接配置顶部展示当前连接摘要，正在使用的卡片显示浅强调背景。启动首帧显示概览，连接内核和自动启动期间显示进度并禁用操作。关闭窗口同时隐藏 Dock 图标；客户端启动后自动启动代理。托盘左键打开主界面，右键显示菜单。

1. 在「连接配置」新增连接，填写服务端、协议、端口和密码。私有 CA 可选择 PEM 文件，TLS 验证名称需匹配证书 SAN。
2. 「校验」只校验，不应用或保存。
3. 「应用并保存」把修改立即应用，并保存到内核配置文件，下次启动恢复；无需单独保存。应用成功但保存失败时明确提示，状态栏显示内核更改尚未保存，可重新点击「应用并保存」。
4. 客户端启动时按内核配置自动开启代理；首次完成配置后可在「概览」启动代理。浏览器 HTTP、HTTPS 代理均指向本地入口，默认 `127.0.0.1:8080`；端口填 0 时由系统分配，概览显示实际地址。

打开客户端会启动或连接管理内核，并按内核当前配置自动开启代理转发；已在运行时直接接管，不重启代理。首次没有连接配置时提示先添加并应用配置；自动启动失败时提示原因，仍可手动启动。关闭窗口会同时隐藏 Dock 图标，托盘与代理继续运行；托盘打开窗口时恢复 Dock 图标。仅重新显示窗口或刷新配置不会再次自动启动代理。

### 开发环境的 Java 25 数字响应异常

AOT 应用不传入 JVM 参数。以下规避只用于开发环境的 JAR 启动：本机复现了 Temurin 25.0.4 运行时在持续序列化空配置状态后，将 JSON 数字写成 NUL 字符的问题；HTTP 响应头中的版本号仍正常。v1.4.1 启动内核时通过 `CompileCommand` 只禁止编译 `com.google.gson.stream.JsonWriter.value(long)`，保持其他即时编译。此项是当前运行时问题的定点规避，不是 JSON 容错解析或旧接口回退；根本的 JVM 编译缺陷仍需由运行时修复。

已有内核必须显式退出再启动，启动参数才能生效。「重启代理」只重启转发，不能替代退出内核。无效响应会显示中文提示，不展示原始正文、不猜测版本号，也不自动重试写入。

## macOS 风格桌面界面

在“设置 → 外观 → 主题”中选择跟随系统、浅色或深色，立即生效并自动保存，无需应用代理配置或重启。默认跟随系统；固定浅色或深色后不受系统外观变化影响。切换外观保留编辑草稿和当前页面。页面、菜单、弹窗、输入框与日志参考 macOS 桌面风格，以 Material 组件和共享主题实现中性灰表面、紧凑分组侧栏、轻量选中态与分段控件；保留系统字体与应用内字体回退，不按操作系统切换视觉风格。界面采用桌面侧栏、紧凑工具栏和分组表单，窄窗口保留侧栏品牌与导航，并调整表单排版，宽窗口限制正文宽度。具体参数见 [桌面 UI 设计规范](docs/desktop-ui-design.md)。macOS 侧栏使用原生半透明磨砂材质，透出窗口后方背景，并跟随当前明暗主题及系统减少透明度设置。原生窗口位置与尺寸仍自动记忆，关闭窗口仍保留菜单栏。

公共标题、区块间距和内容对齐由共享主题管理；保留真实宿主的文本编辑与键盘行为。消息提示使用带语义图标的可关闭面板，连接卡片和列表行随文字缩放调整；处理中同时隔离鼠标和键盘编辑，完成后保留草稿。

- `Ctrl/⌘+1`～`Ctrl/⌘+6`：依次切换概览、连接配置、活跃隧道、路由规则、连接诊断、运行日志；`Ctrl/⌘+,`：打开独立设置面板。
- `Ctrl/⌘+Enter` / `Ctrl/⌘+S`：在连接配置页应用完整配置；在路由规则页只应用直连规则草稿。
- 原生“显示”与“配置”菜单提供同样操作，菜单可用状态与界面同步。
- 概览支持复制本地代理地址；顶部状态显示代理运行或停止，侧栏显示内核连接状态，均由内核实时推送更新。
- 切换页面保留草稿及滚动位置；查看历史日志时停止自动跟随，可点击“跳到最新”恢复。
- 日志导出当前筛选和暂停状态下显示的内容。

## 配置与热更新

- 新增、删除、改名、默认连接切换及连接参数编辑均可在线应用。编辑项目不会自动切换实际代理。
- 修改当前连接的参数或切换默认连接会关闭旧代理隧道，直连隧道不受影响。仅改名不重连。
- 修改直连规则会重新判断已有和正在建立的业务连接，只断开直连/代理结果发生变化的连接，其余连接及共享 HTTP/2、HTTP/3 主连接保持。网段判断可能需要异步 DNS 解析，受影响连接需要浏览器或应用重新请求。路由规则页默认显示可搜索列表，也可切换批量文本编辑；两者共用草稿并保留注释和空行。点击「应用直连规则」只保存这部分修改，连接与本地设置草稿保留。应用时由内核校验，错误显示行号并保留草稿。直连文本文件通过「导入直连文本」预览后追加或替换草稿，不持续引用或监视原文件。
- 修改本地监听地址或端口会立即重建监听，已有连接会断开；绑定失败时内核尝试恢复原监听。修改本地请求超时只影响后续请求。
- 「断开会话」关闭当前代理会话，后续请求重新连接。替换同路径的 CA 文件后也需断开会话。
- 「重启代理」重启转发，使用已应用配置，不重启管理内核。
- 原生应用包直接启动 `Contents/Resources/proxy/network-core`，高级设置显示原生运行环境；Java / JAR 路径设置仅用于 JAR 开发环境，不影响原生应用。已有运行中的内核仍会被接管，切换到新内核程序需先退出 Network，再打开新应用。
- API 返回的密码为空并附带 `hasPassword` 标志。编辑时留空保留原密码，填写则替换；新连接必须填写密码。
- 默认以内核配置为准，首次连接、内核重启或外部配置版本变化时自动同步页面，替换尚未应用的草稿。同版本状态、日志及主题变化不影响编辑。手动「重新读取」有未应用修改时仍会确认是否丢弃。
- 所有配置写入与保存带 `If-Match` 版本；应用后使用本次应用返回的版本保存。冲突时自动读取内核最新配置，提示核对后重新操作，不自动重试写入。概览切换默认连接、启动时应用草稿也会保存到内核。

## macOS 虚拟网卡

代理启动后，概览页可开启「虚拟网卡模式」，首次通过系统管理员授权安装 Outline 系统辅助服务，后续开启通过本机服务启动独立转发进程。直连与代理流量都交给 Java 内核，使用现有统计；TUN 按 IP/CIDR 和全局模式分流，域名规则只适用于显式 HTTP 代理接入。启停会重建现有连接，网络切换后需要重新开启。授权期间关闭开关会撤销本次启动。

系统辅助服务开机待命，但不自动开启 TUN；日常启停不再要求密码，辅助程序更新时需要再次授权。不保存管理员密码，也不持久化开启状态。关闭窗口仍保留客户端及 TUN；退出客户端、停止代理或关闭开关则清理本次路由和 utun。TUN 活动期间需先关闭开关再修改本地监听、重启代理或更新/移除辅助服务。关闭 TUN 后，在「设置 → 虚拟网卡辅助服务」点击「卸载系统辅助服务」，确认并完成管理员授权即可卸载，配置和访问记录会保留；下次开启 TUN 需要重新安装授权。命令行卸载方式见根目录说明。

开发运行和 macOS 打包额外需要 Go 1.25+ 与 C 编译器；`GO` 可指定 Go 路径。构建脚本会应用固定版本的双栈和空 UDP 修复补丁。完整边界、依赖补丁和验证命令见[根目录说明](../README.md#macos-虚拟网卡模式)。

## 生命周期与数据

- 关闭窗口 / Command-W：隐藏主窗口和 Dock 运行图标，保留菜单栏图标，内核和代理继续运行。已固定在 Dock 的快捷方式由 macOS 管理，不会被移除。
- 左键点击托盘图标：恢复主窗口和 Dock 图标，并切换到前台；窗口已最小化时恢复窗口。右键点击托盘图标：显示菜单，可显示窗口、启动或停止代理、退出 Network。重新打开应用也会恢复窗口。
- 菜单栏「退出 Network」、应用菜单「退出」/ Command-Q：先退出内核，再退出客户端。内核已退出、发现文件已移除时清理旧连接状态并直接退出客户端。发现文件仍存在但无法连接、内核退出失败或仍有操作进行时取消退出，恢复窗口并提示；不会强行结束进程。重复退出请求共用同一次关闭操作。
- 停止代理：停止转发，内核管理接口仍运行。
- 页面不再提供单独退出内核的按钮，托盘和应用菜单的退出行为保留。

数据目录为 `~/Library/Application Support/NetworkUI/`：

| 文件 | 用途 |
| --- | --- |
| `kernel.db` | SQLite 配置、流量采样和访问记录，**包含连接密码及访问地址**；macOS 权限为 600 |
| `run/control.json` | 管理地址、令牌、PID 与 API 版本；权限为 600，内核正常退出后删除 |
| `appearance.json` | 本机主题选择（system / light / dark），与代理配置和启动路径独立 |
| `ui.json` | JAR 开发环境的 Java / JAR 启动路径，无密码；原生应用不使用这些路径 |

客户端只通过内核 API 读取和保存代理配置，不读取旧版配置文件，也不访问 macOS 钥匙串。首次使用没有内核配置时，从空配置开始添加连接。证书引用原文件路径，请保留证书文件。规则存入选定数据库，导入后不再依赖原规则文件。应用不会自动改变系统代理。

## 状态、日志与诊断

状态通过带 Authorization 的 SSE 推送，不轮询隧道数量。客户端按完整事件帧解析，断线后通过 `Last-Event-ID` 恢复；收到快照时补齐配置、最近日志与已知诊断任务。内核配置版本变化或内核实例变化时同步页面，同版本快照保留编辑内容。

日志保存最近 500 条，按结构化 `level` 精确筛选，支持暂停、清空显示和导出。UI 在本地筛选完整缓存，切换级别不使用旧筛选游标。内核默认只采集 INFO 及以上级别。日志会脱敏已知密码与管理令牌，但目标域名等仍可能包含使用信息。

v1.4.4 修复精简 Java 运行时中日志采集器与业务日志上下文不同、导致控制台有日志但管理接口为空的问题。采集器显式绑定内核类加载器，并在关闭时从原上下文移除。需要退出旧内核再启动新版才能生效；管理接口只保留本次内核运行的日志，不读取磁盘历史日志。

「隧道列表」展示全部当前业务连接，包含代理、直连、解析中和等待连接的请求；支持按目标、来源、连接名称搜索及按路由筛选，关闭后自动移除。明细使用状态快照和 SSE 推送，要求内核提供 `tunnels` 能力；状态连接断开时明确提示列表保留的是最后收到的快照。内核每 250 毫秒检查变化，不保留已关闭请求的历史记录。

点击隧道的路由选择“切换为代理”“切换为直连”或“恢复自动路由”。覆盖规则精确匹配该域名或 IP 的所有端口，优先于原直连规则，不扩展到子域名。路由变化的已有连接立即断开，由应用重连；同一路由保持。规则自动保存到内核，不修改直连规则原文；在“路由规则 → 指定目标”中可新增、编辑连接方式或移除指定规则。目标规则精确匹配，编辑时不改变目标；需要更换目标时新增规则并移除原项。有未应用的配置草稿时也可切换路由或恢复自动：只保存本次目标路由，保留其他编辑草稿；之后应用草稿会保留最新目标路由。要求内核支持 `targetRoutes` 能力，需通过托盘退出旧版本，再打开本次应用包。

「连接诊断」位于「路由规则」之后，默认测试目标为 `www.google.com:443`，可自行编辑。可选择任一已应用连接建立独立测试会话，显示阶段、累计耗时和错误代码，支持取消；路由查询显示直接连接、代理或无可用代理及匹配依据。成功只代表代理认证和目标 TCP 隧道建立，不代表目标网站的 HTTPS 或页面请求成功。

当前 API 不提供诊断任务列表，因此重新打开 UI 后无法列出之前已经完成的未知任务；具体接口建议见 [适配记录](docs/web-api-adaptation-notes.md)。

## 开发与打包

### JAR 开发运行

需要 Flutter、JDK 25、Maven、Xcode。在 `ui/` 中执行：

```sh
flutter pub get
sh scripts/run-dev.sh
```

开发脚本构建父目录中的 Java JAR，然后启动 macOS 界面。可通过 `FLUTTER` 指定 Flutter 可执行文件，`JAVA_HOME` 指定 JDK，`CORE_ROOT` 指定内核目录；日常开发与验证不执行 Native Image 编译。

### JAR 内核应用包

打包脚本自动读取仓库根目录 `build.local.properties`。首次配置可参考 `../examples/build.properties`，将 JDK、Maven、Go 和 Flutter 路径填写一次；字段和优先级见 [本机构建配置](../docs/build-tools.md)。配置完成后直接执行 `sh scripts/package-macos-jar.sh`。下面的环境变量写法用于临时覆盖配置。

本次概览更新可使用 `scripts/package-macos-jar.sh` 打包，无需编译 Native Image。应用内置最新 JAR 和由 Java 25 `jlink` 生成的运行时，用户无需安装或指定 Java；`network-core` 是使用包内相对路径启动 JAR 的启动器。内核使用当前 SQLite 配置 `kernel.db`，配置写入成功即已保存。

```sh
JDK_HOME=/实际路径/jdk-25 FLUTTER=/实际路径/flutter \
  sh scripts/package-macos-jar.sh
```

此脚本编译 JAR、TUN 辅助程序和 Flutter Release 界面，并进行本机临时签名。应用输出到根目录 `release/ui/Network-YYYYMMDD-HHMMSS.app`，同时更新 `release/client/client.jar` 和 `release/server/server.jar`；不接受自定义输出路径。应用先在构建目录完成组装和签名校验，通过后才发布新包，保留已有 UI 版本。已有发布配置、数据库、证书以及 `Application Support/NetworkUI` 中的 UI 运行数据保持不变。以下 Native Image 打包流程仅在明确需要原生内核时执行。

UI 包名中的时间戳在打包开始时按北京时间（`Asia/Shanghai`）确定，格式为年月日-时分秒，例如 `Network-20261016-103025.app`；同名产物已存在时停止，不覆盖。脚本输出完整产物路径和所在文件夹的 Markdown 链接，交付回复提供可点击的“打开所在文件夹”入口。

### Native Image 内核应用包

要求 Flutter、GraalVM 25（含 native-image）、Maven、Xcode。UI 位于仓库 `ui/`，内核位于其父目录；仅在明确需要 AOT / Native Image 编译时执行：

```sh
GRAALVM_HOME=/实际路径/graalvm-25 sh scripts/package-macos.sh
```

## 代码结构

- `lib/main.dart`：应用入口和系统明暗模式。
- `lib/ui/desktop_theme.dart`：共享 Material 3 主题、字体和桌面设计参数。
- `lib/ui/proxy_home.dart`：窗口布局、生命周期、焦点及确认框。
- `lib/ui/pages/`、`lib/ui/widgets/`：独立页面与共用桌面控件。
- `lib/view_models/proxy_view_model.dart`：编辑草稿、页面状态和操作命令；支持构造注入，原生菜单随状态变化同步。
- `lib/models/`：代理配置，以及只读的连接状态和诊断模型。
- `lib/services/kernel_api_client.dart`：HTTP 请求、认证、超时和错误解析。
- `lib/services/proxy_controller.dart`：内核启动发现、SSE 和已应用状态；日志提供独立通知，不触发整个窗口重建。
- `lib/services/runtime_preferences.dart`：当前启动路径的本地读写。
- `macos/Runner/MainFlutterWindow.swift`：原生菜单与文件选择。

分析启用 `strict-casts`、`strict-inference`、`strict-raw-types`。测试覆盖视图模型、路径存储、系统主题运行中往返切换、草稿保留、日志局部刷新和真实内核联调。


## 长期流量与访问记录

- 概览的“历史流量”固定显示最近一个自然月内已完成小时的发送、接收流量折线。
- “活跃隧道 → 访问记录”按完整域名或IP汇总连接次数、最后访问和最后失败时间；同域名不同端口、协议与路由合并，每分钟保存，正常停止补写，长期保留。旧访问明细由用户手动处理，不自动迁移或删除。
- 数据与配置共用所选数据库。分钟流量在分钟结束和正常停止时落库，不每10秒保存；正常退出会排空待写入记录。强制结束进程或断电可能丢失尚未保存的分钟及待写入队列，数据库错误和队列丢弃会在概览与日志提示。旧历史表由使用者手动处理，不自动迁移或删除。


流量趋势读取分钟表，提供最近1小时、6小时、24小时折线，纵轴为区间发送/接收流量；历史流量固定显示最近一个自然月的小时折线。分钟表保留24小时，小时表保留12个月并在内核启动及凌晨03:00清理。实时速率卡片继续每秒采样，界面只在跨分钟或连接状态变化时刷新趋势。

访问统计支持全部／曾经失败筛选、域名或IP搜索，以表格显示域名/IP、连接次数、最后访问时间、最后失败时间；点击每列标题切换升降序，排序由数据库对全部已保存记录执行。刷新、切换筛选或排序从第一页开始；查询只显示已保存值。实时隧道以表格显示目标地址、原始协议、来源地址、路由/协议、状态和开始时间，每列可点击排序。两个表格固定表头、按需构建行，窄窗口横向滚动；实时推送保留排序及菜单对应的目标。


### 路由规则页

- 顶部显示当前模式和已应用的默认代理；全部直连／全部代理覆盖规则，但不清空规则。模式立即保存，列表编辑仍留在草稿中。
- “这个目标会怎么走？”接受域名或 IP，查询内核已应用规则，显示走向、命中类别及可用的解析地址；不推测具体命中行，不使用尚未应用的草稿。配置版本或内核连接变化后结果标记过期，需重新查询。路由查询不代表真实目标可访问。
- “直连规则”支持新增、备注、搜索、删除、批量文本编辑和导入预览。放弃修改需确认，只恢复直连规则，其他草稿保留。
- “指定目标”入口始终可见；新增和编辑点击“保存并应用”立即生效，移除后按其余规则和默认代理判断，不能保证变为代理或直连。
- 外部配置变化或规则提交版本冲突时保留直连草稿，阻止继续写入旧版本。点击“重新读取配置”确认后放弃所有未应用配置草稿，并读取内核最新快照。


### 配置文件导入与导出

路由页的JSON导入支持合并和整体替换，校验预览后确认生效；只修改规则，保持模式和默认连接。导出保存已应用规则，包含备注。已有草稿需先应用或撤销。

连接页支持选择单个、多个或全部已保存连接导出；“包含密码”默认关闭，勾选后文件含明文密码。导入可作为新连接或明确覆盖同名连接，先进入草稿，再通过现有应用按钮保存。缺少密码的新连接需要补填，自定义证书路径需在本机有效；默认连接不随导入切换。文件不包含本机运行环境与数据库设置。
